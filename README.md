# kentikelenis.net — how this site works

A Quarto site, rendered to `docs/`, served by GitHub Pages at
**https://www.kentikelenis.net**.

## The folder, at a glance

    YOURS — the files you edit
      academic-writing.yml    Articles, chapters, working papers. Drives the Academic writing page.
      policy.yml              Policy reports. Drives the Policy page.
      media.yml               Op-eds and public writing. Drives the Media page.
      index.qmd / about.qmd   Page text (Home, About)
      books.qmd               Book blurbs, review links, Praise expanders
      teaching.qmd            Courses and students
      files/academic writing/ PDFs for academic-writing.yml
      files/policy/           PDFs for policy.yml
      files/media/            PDFs for media.yml
      files/books/            Book PDFs
      files/covers/           Book covers (JPG, ~600x900, fixed names)
      files/cv/               kentikelenis_cv.pdf — overwrite to update
      files/syllabi/          Course syllabi
      files/images/           Hero photo, portrait, favicon

    MACHINERY — rarely touched
      _quarto.yml             Navigation, site title, social links, post-render step
      assets/styles.scss      Colours and fonts
      assets/pub-listing.ejs  How each entry renders (button chips, note lines)
      academic-writing.qmd, policy.qmd, media.qmd, cv.qmd   Thin pages that display the data files
      tools/check_pdfs.py     Verifies every pdf: line against the files on disk
      tools/preflight.py      Full pre-publication check (see below)
      CNAME                   www.kentikelenis.net — do not delete
      docs/                   GENERATED by Render. Never edit by hand.

## The publishing loop

1. Open the project in RStudio. Edit. Save.
2. Terminal: `quarto render`
3. Terminal: `python3 tools/preflight.py` — fix anything reported as an ERROR.
4. Terminal: `cd docs && python3 -m http.server 4321`, open
   http://localhost:4321, click through the pages. Ctrl-C to stop.
   Check over localhost rather than opening `docs/index.html` directly — the
   page scripts behave differently under `file://`.
5. GitHub Desktop: one-line summary → Commit to main → Push origin.
6. Live within a minute or two.

## tools/preflight.py

The single check to run before every push. From the repository root:

    python3 tools/preflight.py

It checks, across all three data files:

- characters in PDF filenames that break a URL (`? # % & +`)
- Unicode normalisation — macOS writes accented filenames in a form that
  GitHub Pages serves as a 404; this catches the mismatch
- PDFs referenced but missing from disk, and PDFs on disk nothing links to
- `code:` values that aren't a substring of their `text:` (the link silently
  disappears when they don't match)
- missing or unknown `cats:`, non-bare DOIs, `http://` links, duplicate
  titles, reverse-chronological order
- after rendering: that `docs/.nojekyll` and `docs/CNAME` both exist

Add `--links` to also test every external URL and DOI. This takes a few
minutes and produces a lot of noise:

    python3 tools/preflight.py --links

Reading the output: **ERROR** must be fixed. **WARNING** deserves a look.
**NOTE** is informational — in particular, publishers (Wiley, OUP, SAGE, IMF,
NYT, Washington Post, UNCTAD) block automated requests, so their `403` and
timeout results mean "bot-blocked", not "dead link". Click one in a browser if
in doubt.

## Adding things

**A new publication, report or op-ed.** Add a block to the right data file —
`academic-writing.yml`, `policy.yml` or `media.yml` — by copying a similar
entry. Types: `article`, `short` (letters/chapters), `report`, `oped`, `wip`.
The page updates itself. Keep entries in reverse-chronological order.

**PDFs.** Name Zotero-style, `Authors - Year - Title.pdf`, and drop the file
into the folder matching its data file. Then add a `pdf:` line to the entry
with the path exactly as the file is named. Two rules that save grief:

- no `?` in the filename — strip it from the title (`Just Talk?.pdf` becomes
  `Just Talk.pdf`)
- accented names: run preflight afterwards, which catches the macOS
  normalisation problem

Buttons are purely data-driven: a PDF, DOI or Replication button exists only
if that field exists in the entry. There is no runtime check for whether the
file is really there — that's what `check_pdfs.py` and `preflight.py` are for.

**Praise quotes.** `books.qmd` → search "praise" → edit the text inside each
`<blockquote>...</blockquote>` and the source inside `<em>...</em>`. Copy a
blockquote line for more quotes.

**Book covers.** Save as JPG (~600x900), name exactly as in `files/covers/`,
drop in. Nothing to edit.

**Links on "Reviewed in" / "Cited in" / "Award" / "Coverage in" lines.**
Under the item, add a `url:` and a `code:`. The `code:` must appear **word for
word** inside the `text:` — that substring becomes the link, and the rest stays
plain. Watch for em dashes and curly apostrophes when copying. Preflight
flags any mismatch.

For op-eds, `url:` goes on the entry itself, no `code:` needed. In
`books.qmd`, replace the `#` in `<a href="#">Outlet</a>` with the URL.

**Favourites.** The 🥰 tag comes from `fav:` in the entry. The filter pill is
deep-linkable at `/academic-writing.html#fav`.

## Hosting and domain (set up once — reference only)

- **GitHub Pages**: repo Settings → Pages, deploying from branch `main`,
  folder `/docs`. Custom domain `www.kentikelenis.net`, Enforce HTTPS on.
- **GoDaddy DNS**: four A records on `@` pointing to `185.199.108.153`,
  `.109.153`, `.110.153`, `.111.153`, plus a CNAME on `www` pointing to
  `akentikelenis.github.io`. No domain forwarding.
- **CNAME file** at the repository root contains `www.kentikelenis.net` and is
  copied into `docs/` on every render via the `resources:` block. Deleting it
  breaks the custom domain.
- **`.nojekyll`**: `_quarto.yml` has `post-render: touch docs/.nojekyll`,
  because rendering clears `docs/` and GitHub Pages needs that file present.
  If preflight ever reports it missing, the post-render line has gone astray.

## Applying updates from Claude WITHOUT losing your edits

Rule one: after the first install, never unzip a whole site over this folder.
Updates arrive as individual files with stated destinations.

Safe procedure every time:

1. Commit your own work first (GitHub Desktop → Commit). Your edits are now safe.
2. Drop in the file(s), each to its stated destination.
3. GitHub Desktop shows exactly what changed, line by line. Anything unwanted:
   right-click the file → Discard changes.
4. Render, run preflight, check on localhost, commit, push.

Because the folder is a git repository, every committed state is recoverable —
GitHub Desktop → History → right-click a commit → Revert. Nothing committed is
ever lost.

Special case, the three data files: they are both yours (links, awards, praise)
and frequently edited. Prefer sending the current file to Claude and asking for
a merged version back, then re-check your recent edits in the GitHub Desktop
diff before committing.

## When something breaks

- **A PDF button 404s on the live site but works locally.** Almost always a
  `?` in the filename or a Unicode normalisation mismatch. Run preflight.
- **A "Cited in" link doesn't appear.** The `code:` doesn't match the `text:`
  character for character. Run preflight.
- **The whole site loses its styling after a push.** Check that
  `docs/.nojekyll` was committed.
- **The domain stops resolving.** Check that `docs/CNAME` still exists and
  that Settings → Pages still shows the custom domain.
